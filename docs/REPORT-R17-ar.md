## 1. الفجوات الخمس التي أُغلقت

| # | الفجوة (بعد R1) | قبل R17 | بعد R17 |
|---|---|---|---|
| 1 | `cwc_cycletime` (بايت 18) | يُتجاهل ويُصفَّر | يُعاد توجيهه حرفيًا (خيار `cacheex_cwcfwd`) — لا نُفسِّره أبدًا |
| 2 | قائمة العقد | `[أنا, الأصل]` فقط — التاريخ يُفقد | `[أنا, …التاريخ]` حتى 10 (شكل oscam) — تاريخ العبور يبقى |
| 3 | بوابة rc عند الاستقبال | غير مفحوصة (0x64/100 يُخزَّنان CW) | خيار `cacheex_rcfilter`: E_FOUND فقط (موثَّق أدناه) |
| 4 | جدول push-filter (0x3C/0x82) | يُهمَل بصمت | يُخزَّن لكل نظير ويُحترم على إرسالنا له (`cacheex_pushfilter`) |
| 5 | حماية الحلقات | فحص العقدة الأولى فقط (فرع camd35) | `cacheex_nodeloop`: قطرة استقبالية + تخطٍّ إرسالي بقائمة كاملة |

وأُعيد تثبيت تبادل الهوية (0x3D/0x3E) كسلك مُختبَر: `CAMD_CEX_IDREQUEST`
يجيب بـ 0x3E يحمل هويتنا، والردّ يُخزَّن هوية النظير (cli-camd35 كان
يقبل 0x3E فقط — أُضيف ردّ 0x3E للطلب الوارد).

## 2. سطح الإعداد (الجديد كله OFF افتراضيًا)

مفاتيح لكل نظير داخل بلوك المستخدم (`CAMD35 USER`/`CS378X USER`/`F:`)،
بنفس صيغة `cacheex_mode`:

| المفتاح | الافتراضي | الوظيفة |
|---|---|---|
| `cacheex_cwcfwd` | 0 | تمرير `cwc_cycletime` كما وصل على إعادة الإرسال (0 = الصفر كما r82a) |
| `cacheex_rcfilter` | 0 | قبول rc==E_FOUND (0) فقط؛ 100/غيره يُسقط + سطر DEBUG (0 = r82a يقبل ما جاء) |
| `cacheex_pushfilter` | 0 | تخزين جدول push-filter الوارد (0x3C/0x82) وإلحاقه بإرسالنا لذلك النظير (0 = الجدول يُهمَل كما r82a) |
| `cacheex_nodeloop` | 0 | استقبالًا: إسقاط أي push تحوي قائمته هويتنا؛ إرسالًا: تخطّي هدف ظهر في القائمة (0 = فحص r82a للعقدة الأولى) |

## 3. السلوك الحدّي (كل بند مُختبَر في `r17`)

1. **بوابة rc (P2):** مع `rcfilter=1` يُسقَط push بـ rc=100 (E_UNHANDLED —
   «بلا CW» وليس CW) قبل التخزين والإعادة؛ rc=0 يمرّ (ضبط إيجابي).
   بلا الخيار يقبل r82a كل rc (كما كان — موثَّق لا مُصلَّح).
2. **الحلقات (P4-recv/P4-send/P4-gap):** مع `nodeloop=1` يُسقَط push
   زارت قائمته هويتنا (الدورة A→B→C→A تُكسر عندنا)؛ وإرسالًا يُتخطّى
   الهدف الظاهر في القائمة. **الحدّ الموثَّق:** بوابة r82a
   `maxhop>uphop` (maxhop مسقوف بـ 2) تمنع أصلًا إعادة أي push وصل
   بقائمتي عقد فأكثر — فالإعادة البعيدة تُطلق فقط لِـ push بعقدة واحدة،
   حيث يتفق فحص القائمة الكاملة مع فحص r82a للعقدة الأولى. فحص القائمة
   الكاملة يصبح فارقًا حقيقيًا عند إطلاق MAXHOP_LG (المُعلَّن «غير
   مُنفَّذ» منذ R1) — وهو جاهز ومحفوظ بالاختبار. والبند الموثَّق كفجوة
   قديمة (P4-gap): **r82a يقبل push زارته قائمته** (لا قطرة استقبال
   أصلًا) — والخيار يقلب ذلك.
3. **cwc_cycletime (P0/P1):** مع `cwcfwd=1` يُعاد البايت حرفيًا (0x88
   تصل 0x88)؛ بلا الخيار يُصفَّر كما r82a. نحن لا نتصرف بحسبه إطلاقًا
   (وسم الدورة يبقى عمل آليات cwcycle المحلية).
4. **push-filter (P3/P3-off):** مع `pushfilter=1` يُخزَّن الجدول ويُحترم
   (sid خارج القائمة لا يُرسَل — والمخزَّن يبقى كما هو؛ المرشِّح يحكم
   الإرسال لا التخزين)؛ بلا الخيار يُهمَل الجدول ويمرّ كل شيء كما r82a.
5. **قائمة العقد:** إرسالاتنا تحمل `[هويتنا, …التاريخ الوارد]` — العقدة
   الأولى كما r82a (أقدم نظير يقرأها وحدها ويصحّ فحصه)، والبقية لفحوص
   حلقات r107.

## 4. سلك oscam مُثبَّت لا مُخمَّن

`src/cexwire.h` يحمل تخطيط السلك كاملًا (push camd35+cccam، جدولا
المرشِّح 15/30 خانة، تطابق `chk_csp_ctab` ببنية الإشارة كما في oscam)،
و`make-x64/test_cexwire.c` (64 فحصًا) يبني الإطارات **بايتًا ببايت من
تخطيط مصدر oscam** (module-camd35-cacheex.c، مُتحقَّق منه 2026-10-12 عبر
api.github.com) ويقارن — لا عبر مُحزِّمنا مرتين. الدقيقة الذهبية: قائمة
العقد `[المرسِل, …التاريخ]` هي شكل oscam نفسه.
