# تقرير المهمة 3.7 — مُحلِّل الإعداد يحفظ الفاصلة الصفرية داخل المخزن (parser.c)

التاريخ: 2026-09-26 · الخطة: PROJECT-PLAN-ar.md — الحزمة أ، رأس الطابور.

## 1) العيب — بايت واحد خارج الحد، في ست دوال، منذ r82a الأصلية

ست دوال في parser.c تشتركن في الكاتب نفسه: `parse_str` و`parse_name`
و`parse_value` و`parse_int` و`parse_hex` و`parse_bin`:

```c
if (len>=255) len=255; // check for length
memcpy(str, iparser, len);
str[len] = 0;          // ← len قد يكون 255 بالضبط
```

فأي رمز إعداد بطول ≥255 حرفاً يكتب الفاصلة الصفرية في `str[255]` —
**بايتاً واحداً خارج** أي مخزن `char str[255]`. والطبقة تغذّي مخازن
حقيقية بهذا الحجم: scratch دالة `read_config` نفسها (config.c:845)،
وscratch دالة `parse_server_data` (:487)، و`twin_read_chninfo`
(:4477)، و`parse_boolean` تملك واحداً بنفسها. في بناء الإنتاج الكتابة
غالباً صامتة (حشوة مجاورة) وأحياناً قاتلة (مؤشّر أو عدّاد مجاور) —
من فئة الفساد الكامن الذي لا يظهر إلا بعد سنوات.

ملاحظة نطاق (D37): الخطة سمّت دالتين؛ التحقق وجد ستاً بالكاتب نفسه،
فأُصلحت الست كلها في فئة رقعة واحدة — بنمط 1.10a←1.10c.

## 2) الأدلة — قبل/بعد

**الوحدات (36 تأكيداً، `test_parser` المجموعة 28):** بنية canary
مصفوفة بحيث تجلس بايت الشاهد عند الإزاحة 255 — بالضبط موقع الكتابة
القديمة — لكل دالة من الست × {رمز 254 كامل، 255 مقصوص، 400 مقصوص،
فارغ، الشواهد}. قبل الإصلاح: **15 فشلاً** (كل رمز 255 يكل الشاهد
ويُرجع len=255). بعد الإصلاح: **36/36**.

**حيّاً على السيرفر الحقيقي تحت ASan** (أداة جديدة دائمة:
`x64/multics-asan` — main/parser/config مُرقَّعة، البقية كائنات
عادية، مع `-fsanitize-recover` ليُبلِّغ كل المواقع في تشغيل واحد):
إعدادٌ واحد بثلاثة رموز بطول 255 أنتج قبل الإصلاح **8 تقارير**
`WRITE of size 1` stack-buffer-overflow في إقلاع واحد، بينها:

```
WRITE of size 1 ... in parse_value ../src/parser.c:80
    #1 parse_boolean ../src/parser.c:119      ← مخزن parse_boolean الخاص
WRITE of size 1 ... in parse_str ../src/parser.c:96
    #1 read_config ../src/config.c:3497       ← scratch read_config الحقيقي
```

وبعد الإصلاح، نفس الإعداد ونفس الأداة: **صفر تقارير**.

## 3) الإصلاح (D37)

سقف واحد تغيّر في ستة أسطر موسومة `TASK 3.7`: `len=254` — الفاصلة
تسقط عند `str[254]`: داخل كل مخزن 255، والسلسلة تبقى منتهية. رموز
254 كانت وتظل كاملة؛ 255+ تُقطَّع حرفاً واحداً أبكر، بصمت كما كانت
تُقطَّع أصلاً. لا تحذير جديد (الدوال الست بلا سياق سطر إعداد)، ولا
تغيير توقيع، ولا لمس لمواقع الاستدعاء (~40 موقعاً استفادت دفعة
واحدة).

**سُجِّل لا يُدمَج:** `parse_quotes` تنسخ بـ`strcpy` غير محدود (يتطلب
علامة اقتباس في السطر؛ يصلها `HTTP TITLE`) — مهمة تالية؛ والفروع
الست الشقيقة USER/PASS (D35) تبقى لها المهمة 3.8.
