# MultiCS R200 v2.6 — Feature & Enhancement Guide

**Version:** v2.6 (REVISION 200)
**Build line:** SuperSmartFilter R200 V6.7 → V6.17 + v2.6 hotfixes
**Scope:** everything added to the R200 line after v2.5, including the new
anti-fake CW detectors, IP auto-ban rework, console improvements, and the
v2.6 security hardening.

## 2. SmartFilter: the new detection engine

### 2.1 DCW MARCHCHECK — same-slot recycled CW

On a legitimate full-CW "marching" channel, two consecutive CWs share one
half:

```
(CW0, CW1) → (CW1, CW2) → (CW2, CW3) ...
```

The shared half alternates slots every cycle. A fake produced by recycling a
CW keeps a half parked in the **same slot** for two or more consecutive
accepts. MARCHCHECK detects that pattern.

```ini
# inside a profile (CAID block)
DCW MARCHCHECK : 0    # off (default)
DCW MARCHCHECK : 1    # log-only (writes to the antifake log)
DCW MARCHCHECK : 2    # hard-reject the CW
```

Channels configured as tag-cycled (`cw1cycle` 0x80/0x81) are exempt because
they legitimately reuse a half in the same slot. A *learned* cycle does not
disable the detector — a learned wrong-cycle comes from already-poisoned CWs
and is exactly what is being hunted.

### 2.2 Exact Shannon entropy, mirror and duplicate fakes (V6.7)

Ported from the OSCam v9.4 proxy anti-fake logic:

- Exact **Shannon entropy** per CW, with separate thresholds for full and
  half CWs:
  - `SF_ENTROPY_FULL` (default **2.5**, scale 0..4.0)
  - `SF_ENTROPY_HALF` (default **1.5**, scale 0..3.0)
  - `SF_ENTROPY` is the master switch (default **0**).
- **Mirror** fake: every byte is the logical complement of a legitimate half.
- **Duplicate** fake: all-zero or all-FF valid half.
- Multicheck now **normalizes** half CWs to a canonical 8-byte form before
  comparison, so equivalent representations compare equal.

### 2.3 Multicheck per profile (V6.8 → V6.8d)

Multicheck can be enabled for one CAID without touching the global switch:

```ini
# inside a profile
DCW MULTICHECK : YES          # or NO / 1 / 0
DCW MULTICHECK CWMATCH : 2    # peers that must agree (1..10)
DCW MULTICHECK CWMIN : 3      # if > 0, replaces CWMATCH
DCW MULTICHECK WAITTIME : 500 # consensus window in ms (0 = global)
DCW MULTICHECK ENTROPY : 3.5  # minimum CW entropy for this CAID
```

Global defaults:

```ini
SF_MULTICHECK : 0             # off by default
SF_MC_CAIDS :                 # empty = all channels
SF_MC_MATCH : 2               # 1..10
SF_MC_MODE : 1                # 1 = log-only, 2 = reject
SF_MC_MODE_LOG_ONLY : 1       # self-documenting alias for log-only
SF_MC_WAIT : 200              # ms, 50..5000
```

> **Strictness warning:** `SF_MC_MATCH = 2` with `SF_MC_MODE = 2` is very
> strict. A channel served by a single peer will be rejected. When in doubt,
> start with mode 1 (log-only) and raise MATCH or lower the scope.

`SF_MC_CAIDS` remains the master gate: an empty list means every CAID.

### 2.4 New filters (V6.9)

All default **off**; enable after a smoke test.

| Keyword | Default | Purpose |
|---|---|---|
| `SF_WHITELIST_IPS` | empty | Trusted peer IPs exempt from all fake checks |
| `SF_SUSPICIOUS` | 0 | Flag suspicious CW reuse on different SIDs |
| `SF_SUSPICIOUS_RATIO` | 30 | Bad-key ratio (%) applied while suspicious |
| `SF_LATECW_MS` | 0 | Reject CWs arriving later than this (ms) |
| `SF_CW_CHECK` | 0 | CW integrity / first-half re-check (0=off, 1=NDS, 2=all but E0) |
| `SF_ICAM` | 0 | iCAM burst guard |
| `SF_ICAM_COOLDOWN` | 10 | Per-peer cooldown seconds (1..3600) |

### 2.5 Constant / conflicting CW — `SF_CW_DUP` (V6.12)

Catches a fault where the same CW is repeated many times while other distinct
CWs exist for the same channel (the classic black-screen fake).

```ini
SF_CW_DUP : 1        # default 0 (off)
SF_CW_DUP_REP : 4    # repetitions before flag, 2..10 (default 3)
```

A genuine constant CW (one key, no competitor) and a normal key roll (two
distinct keys) are never flagged.

### 2.6 Half-CW clone detection (V6.14 → V6.16)

Fake generators in the wild recycle a small pool of 8-byte halves across
channels. Three complementary checks:

**Cross-channel reuse — `SF_CW_REUSE` (V6.14)**

```ini
SF_CW_REUSE : 1                 # default 0
SF_CW_REUSE_WINDOW : 120000     # ms, 1000..600000
SF_REUSE_CAIDS : 1814,1802      # empty = all CAIDs
```

A half already seen on a **different** `(caid, sid)` inside the window is
rejected (`REUSE`). Same-channel re-sighting refreshes and never flags; a
stale cross-channel sighting adopts the new channel.

**Chain validation — `SF_CW_CHAIN` (V6.15)**

```ini
SF_CW_CHAIN : 1                 # default 0
SF_CHAIN_WINDOW : 4000          # ms, 500..60000
SF_HALFCW_CAIDS : 1814,1802     # full-CW CAIDs that must march
```

A new CW on a listed channel must share exactly one half with the previous
accepted CW; otherwise it is rejected (`HALFCHAIN`). Only list **full-CW**
CAIDs here — NDS half-nulled CWs have no predictable next half.

**Intra-channel pool recycling — HALFREUSE (V6.16)**

A half seen **3 or more times** with a different peer half on the same
`(caid, sid)` inside the chain window is rejected (`HALFREUSE`). A legitimate
Nagra channel carries each half exactly twice.

**CHAIN and REUSE now run independently.** Previously REUSE was silently
skipped while CHAIN pre-empted on the same CAID.

> **Naming note — do not confuse the two lists:**
> - `SF_HALF_N_CW_CAIDS` = NDS half-CW expectation list.
> - `SF_HALFCW_CAIDS` = full-CW chain-validator list.
>
> They were renamed in V6.15; the old single name was ambiguous.

### 2.7 NDS-family half-CW seed (V6.17)

NDS/Videoguard sends only the current 8-byte half; the receiver must expect a
48-bit CW. The family seed makes that expectation explicit:

```ini
SF_HALF_N_CW_CAIDS : 098D,0960,0961,0963,09BD,098E,092F,091F
SF_HALF_NDS_FAMILY : 1    # optional: treat every NDS CAID as half
```

- 09C7 and 09EF are **excluded** from the family because they send
  current + previous CW (16 bytes, full format).
- A seeded expectation is **log-only** and can never drop a CW by itself.
- The learner still wins: a decided 48/64-bit format overrides the seed.
- A wrong family seed cannot black-screen a channel (fail-open).

## 3. IP management and auto-ban

### 3.1 Per-protocol bans (V6.8c)

The IP list now keeps one flag per protocol instead of a single "all"
flag. An expired client is banned under **its own** protocol, not the whole
box.

- CCcam, Newcamd, Mgcamd, CS378x, Camd35, Cache, CacheEX and FreeCCcam can be
  blocked independently.
- A block with no protocol still means **ALL**.
- An existing "ALL" entry can be narrowed to individual protocols.

### 3.2 Unban controls

- **Per-protocol Unban buttons** on `/iptables` (V6.8c): CCcam, Newcamd,
  Mgcamd, CS378x, Camd35.
- **Unban ALL** (V6.10): flushes every blocked IP and removes all MultiCS
  iptables rules in one click.
- Unbanning a protocol converts an `ALL` entry into explicit flags and only
  removes the requested one; the entry disappears when no flag remains.

### 3.3 Web brute-force protection (V6.13)

- Failed web logins are counted; after `HTTP LOGIN FAILS` the source IP is
  banned for `HTTP LOGIN BAN` seconds.
- Login attempts are recorded in the audit log and shown on `/loginlog`.
- `HTTP SESSION TIMEOUT` and `HTTP SESSION IDLE` control absolute session
  lifetime and idle expiry.

## 4. Web console and monitoring

### 4.1 `/iptables` standalone console (V6.11)

The page now uses the same shared light theme as the rest of the interface
(`http_write_style`), with:

- real console menu bar and Home button;
- `sbutton`-style Block / Unban / Unban ALL buttons;
- status cards for Auto-Ban, fail threshold, ban duration and targets;
- live blocked-IP table with per-protocol unban links.

### 4.2 `/loginlog` audit page (V6.13)

Shows the web login history: user, source IP, result, timestamp. Useful for
detecting brute-force attempts and for support.

### 4.3 SmartFilter console

- New counters and pills for `REUSE`, `HALFREUSE`, `CHAIN`, `DUP-CW`,
  `ENTROPY`, `MIRROR`, `FMT`, `STRBL`, `MULTICHECK`, `LATE`, `CW-CHECK`,
  `iCAM`.
- **Log filter buttons** (All / REUSE / DUP-CW / MC / FMT / LATE / CHECKSUM /
  MIRROR / BLOCK) on the Logs tab.
- Per-profile multicheck overrides are visible in the console (`mc_prof`).
- The full SmartFilter chain now also applies to **server-sourced** CWs
  (V6.13), not only cache peers.

### 4.4 Cache page

- Strongest / Bad filters use the share of total cache hits (>1% = Strongest,
  <1% = Bad), with no unfair blocking of high-volume peers.
- Cache-peer `profiles=` allow-list: a peer can only deliver to the profiles
  listed in its config block (empty = all).
- The handshake advertises `r200 v2.6`; the remote peer's advertised version
  is shown in the prog column.

## 5. Security and stability (v2.6 hotfixes)

- **Bounded debug formatting (`debug.c`)** — `mlogf` uses `vsnprintf`, the
  format copy is clamped with `strncpy(..., sizeof(fstr)-1)`, the log level is
  bounded to 0..5, and the debug ring index uses an atomic, cast-safe
  increment. This removes the debug logger stack overflow described in the
  v2.5 feedback.
- **cs378x pollfd capacity guards (`srv-cs378x.c`)** — both receive threads
  now use a 1024-entry pollfd array (`MAX_CS378X_POLLFD`) instead of the
  200-entry `MAX_CSPORTS`, with a strict capacity check before every append.
  This prevents stack smashing under high client loads.
- **camd35 packet-length validation (`msg-camd35.c`)** — `cs378x_recv` and
  `cs378x_msg_peek` reject `newlen > 2048` or `<= 0`; `cs378x_send` rejects
  `len < 0` or `len > 1000` before touching its 1024-byte send buffer.

> **Scope note:** these are defensive bounds. They are not a substitute for a
> full protocol fuzz audit; keep the server behind your usual firewall and do
> not expose CS378x to untrusted networks.

## 6. Configuration reference

Syntax rules:

- Keywords can be written with or without the `CACHE ` / `DEFAULT ` prefix.
- The separator can be `:` or a space.
- Per-profile fields go inside a `CAID:` block.
- Restart (or config reload) after changes.

```ini
# all of these are valid
SF_FILTER: 2
CACHE SF_MULTICHECK : 1
DCW MARCHCHECK : 2
```

## 7. Upgrade notes

1. **Existing configs remain valid.** All new detectors default to off or
   log-only, except the marchcheck value you explicitly set per profile.
2. **Test on one server first.** Enable one detector at a time and watch the
   SmartFilter console and `/var/log/supersmartfilter.log`.
3. **Recommended rollout:**
   - Start with `SF_CWFMT_AUTO: 1`, `SF_CWFMT_ENFORCE: 1` (log only).
   - For Nagra marching channels: `SF_CW_CHAIN: 1` + `SF_HALFCW_CAIDS` list,
     then `DCW MARCHCHECK: 1` (log) before `2` (reject).
   - For NDS channels: `SF_HALF_N_CW_CAIDS` with the NDS CAIDs.
   - Multicheck: `SF_MC_MODE: 1` first; raise `SF_MC_MATCH` only where enough
     independent peers exist.
4. **Do not put NDS half-CW CAIDs in `SF_HALFCW_CAIDS`.** That list is the
   chain validator and expects full CWs. Use `SF_HALF_N_CW_CAIDS` for NDS.
5. After a config edit, restart the daemon (or let the reload path apply it)
   and verify the startup `config final:` line reports the expected values.
