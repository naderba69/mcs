# تقرير TASK 3.13 — رصيد البطاقة عند −100 يعود — 2026-09-26

## الخلاصة بالعربية الواضحة

رصيد القناة على البطاقة كان يتجمّد عند −100 ولا يعود أبداً. نجاح لاحق
لا يصفّره، فتبقى القناة مستبعدة ما دام خيار `DCW MAXFAILED` مضبوطاً،
حتى إعادة تشغيل الخادم. هذا هو السبب 3 في وثيقة الشاشة السوداء.

الآن الأرضية سقف لا قفل:

- مئة فشل تُظهر العداد عند **−100**.
- خمسون فشلاً بعدها تبقيه عند **−100**. لا ينزل أكثر.
- نجاح واحد يعيده إلى **0**. القناة تعود صالحة للاختيار.
- السقف **+100** كما كان. لم يُمس.
- عقوبة الرفض نفسها كما كانت: مفتاح مرفوض ما زال ينقص الرصيد بواحد.
  ما تغيّر هو أن الأرضية لم تعد قفلاً.

بلا سطر `DCW MAXFAILED` (القيمة الافتراضية 0) البوابة مفتوحة أصلاً،
والرصيد لا يستبعد البطاقة. الشاشة السوداء كانت تظهر حين يضبط المشغّل
الخيار (بين 1 و100).

عند بلوغ الأرضية يُكتب سطر واحد:

```
!!! CARDSIDS: prov:sid 000000:0164 at floor -100; a later success still recovers
```

وعند التعافي سطر واحد:

```
!!! CARDSIDS: prov:sid 000000:0164 recovered from the floor
```

الفشل بعد الأرضية لا يكرر السطر.

## الدليل

الدالة التي اشتُغلت هي `cardsids_update` في `main.c` نفسها، لا نسخة
اختبار. الخادم اشتغل ومعه البوابة التي تقرأ هذا الرصيد.

| الفحص | النتيجة |
|---|---|
| بعد 100 فشل | العداد يظهر −100 |
| بعد 50 فشلاً إضافياً | يبقى −100 |
| نجاح واحد | يعود إلى 0 |
| سطر الأرضية | مرة لكل مزوّد، لا في كل فشل لاحق |
| سطر التعافي | مرة واحدة |
| السقف +100 | لم يتحرك، حتى بعد فشل |
| مزوّدان على البطاقة نفسها | لكل واحد رصيده |
| صفحة البروفايل | `DCW MAXFAILED` = 100 |
| الخادم | حلّل الإعداد وأنهى الإقلاع وبقي حيّاً |
